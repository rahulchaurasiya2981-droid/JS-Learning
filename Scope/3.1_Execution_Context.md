Working of js
---------------

1. Execution context
---------------------
- Everthing in js happens inside an `Execution context`
- Execution Context is the environment in which JavaScript code is evaluated and executed
- Two phases : 
    A. Memory creation phase (variable environment)(memory component)
        - Store in `key : value` formate (variable and functions)
    B. Code execution phase (thread of execution)(code component)
        - containe whole js code
        - execure one command at a time in specific order so we called the js is `synchronous single-threaded` language.

- `return` keyword is used to return the controlle back to place where it is called.
- when `js code` is ready it will create `global executon context`
- and when `function` is called a new `function executions context` is created.
- this all execution context is manage by the `callstack` by push and pop.

- `Hoisted` means created in memory
- In JavaScript, `var` variables are `hoisted` and `initialized` with `undefined` during the `memory creation phase`, so they can be accessed `before declaration` without errors.
- `var` → `hoisted` and initialized with `undefined` (stay in memory phase)
- `let` & `const` → `hoisted` but `NOT initialized` (stay in TDZ)


Types of Execution context
---------------------------
1. Global Execution Context (GEC)
- Default context created when your `JS program starts`
- Created `only once`
- represents the global scope   
- In GEC : this === window (haveing same reference value)
```js
var x = 10;

function test() {
  console.log("inside function");
}
```

2. Function Execution Context (FEC)
- Created every time a `function is called`
- New context for each function call
- Has its own: variables, arguments and scope chain
- After execution → gets destroyed and control back to place where it is called.

```js
function greet() {
  let msg = "Hello";
  console.log(msg);
}

greet();
```

3. Eval Execution Context (Rare ⚠️)
- Created when eval() function is used
- ⚠️ Not recommended to use cause have (security + performance issues)
```js
eval("var x = 10; console.log(x);");
```

Each context has 2 phases:
---------------------------
1. Memory Creation Phase
- memory allocation of the variabl and function happen
- `var` is hoisted and intialized with undefined
- `let/const` is hoisted but not uninitialized (TDZ)
- `Function declarations` are fully hoisted (mainly stored in heap memory) (full function stored)

2. Execution Phase
- Code runs line by line
- Values assigned
- Function call & executions


Note : `Execution contexts are managed` using Call Stack (LIFO)
